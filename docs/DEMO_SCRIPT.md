# Three-minute demo script

Target runtime: **2:50**, leaving ten seconds for video variance.

## 0:00–0:20 — The right is easy to promise, hard to prove

Show the EraseGraph landing page and scroll to the live operational case file.

> Maya withdrew consent for model-training use. Her data exists as a training profile, embedding row, audio object, and transcript. Her active account, audit receipt, billing artifacts, and held records must remain. EraseGraph turns that request into one reviewable, verifiable operation.

Point to `ER-2048`, the verified identity prerequisite, the one-month deadline, the purpose scope, and the four-erase/six-retain impact. Open the complete case.

## 0:20–0:45 — Real stores, not a storyboard

Use **Sync now**, switch from **Graph** to **Ledger**, search for `billing`, then filter **Retain**. Return to the graph and open the live record sheet for Postgres, then MinIO. Mention that the UI is polling the control plane and that reset reseeds both stores.

> These are synthetic records in real local Postgres and MinIO. No compliance claim and no hidden production data.

## 0:45–1:25 — TrueForge does the work

Open the embedded TrueForge console and send the prepared mission prompt.

Narrate only the important capabilities:

- Three subagents discover Postgres, MinIO, and the retention policy in parallel.
- The sandbox reconciles their outputs into a canonical plan using only built-in language APIs; no dependency download is needed.
- Read-only MCP calls populate the live purpose graph.

Pause on the result: four deletions and six explicitly retained records. The request itself carries the purpose withdrawal; EraseGraph preserves only a minimal consent-history receipt as evidence.

## 1:25–1:55 — The safety boundary

TrueForge pauses before `execute_approved_plan`.

> This is not a decorative confirmation modal. TrueForge has stopped the session at the destructive MCP tool. The control plane will also reject an edited, stale, or policy-violating plan even if a model tries to submit one.

Show the exact plan hash, deleted objects, withdrawn consent, and retained invoice/account. Approve.

## 1:55–2:30 — Prove the postcondition

Watch the graph transition to verified states.

> Execution is idempotent. A separate verification tool now re-queries both stores: scoped training records are absent; retained records are still present. Agent narration is not accepted as proof.

Open the evidence packet and point to event hashes, previous-hash links, plan hash, verification totals, and zero failures.

## 2:30–2:50 — Close on the three tracks

> EraseGraph makes TrueForge's harness the product boundary: subagents investigate, sandboxed code reconciles, an exact approval authorizes, deterministic policy constrains, and independent reads prove. The result is safer automation, tested code, and an interface a privacy operator can actually use.

End on the verified graph and tagline: **Right to erasure, with evidence.**

## Recording checklist

- Use a 1440p capture and browser zoom that keeps the full graph readable.
- Reset immediately before recording.
- Preconfigure the model, MCP server, agent, and sandbox.
- Keep Postgres, MinIO, the control plane, TrueForge, and the web app already running.
- Rehearse the approval pause so the cursor lands on the exact diff.
- Do not speed through the safety moment; it is the central scene.
- Avoid showing API keys, terminals containing secrets, personal notifications, or unrelated browser tabs.
